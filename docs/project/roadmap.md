# 路线图

这里只写当前目标、下一步和明确不做的事；已完成的工作不在这里记账。

当前能力与边界见根目录 [`README.md`](../../README.md#能力与状态)，验证分层与命令见
[`docs/project/spec/testing.md`](spec/testing.md)。

## 当前目标：v1.0

架构已经成立：原版 Nukkit-MOT + `Mukkit.jar` + 未修改的 `.phar`，由 PocketMine 自己的
`PluginManager` 加载。剩下的风险不在"能不能桥"，在**没人用过**。

目标从"能吃下 PM 插件"（一个开放命题，永远没有完成的那一刻）换成三条可以被证伪的承诺：

| 承诺 | 判据 | 现状 |
|---|---|---|
| **真机能跑** | 一份有名字的插件清单，真客户端逐条通过 | 12 条里 8 条通过，见 [`smoke.md`](../operations/smoke.md) |
| **加载前说得清** | 任何 `.phar` 给出档位 + 原因码，不是"试试看" | 只有 `StubProfile::UNSUPPORTED` |
| **跑得住** | 2 小时 / 20 人 / 跑图：RSS 有上限、p99 tick < 5ms、宿主崩了世界不丢 | 未测 |

能力面扩张是**副产品**：先有失败清单，再决定桥什么。每条工作带"过不了就停手"的判据。

## 下一步

### 真机测试（L4）

清单与操作步骤见 [`smoke.md`](../operations/smoke.md)。这一阶段结算表单、计分板、背包、实体、
方块、命令、踢人等真机项。判据是**能上服**，不是"桥内又绿了一遍"。

两条路，都走：

- **网易开发者客户端（macOS 本机，可脚本化）**：用外部客户端自动化驱动连本机服，能截图、
  输入、点击 UI、跑客户端 Python 探针。**它必须在用户自己的终端里跑**：启动器要调
  `sandbox-exec`，而 Agent 的进程树已在沙箱里，嵌套会被系统拒绝（退出码 71）。
- **真实玩家客户端（手机 / PC 国际版）**：手工，负责"换一个客户端版本"。
  网易版与国际版的协议版本不同，**不能用前者替代后者**。

`scripts/serve.sh` 起一个可连的服务端（固定端口、`xbox-auth=off`、探针全装、前台运行）。

- 判据：12 条里过 10 条，且每条都有日志或截图
- 停手条件：不足 6 条 → 包映射层有系统性错误，暂停扩面，先修这一层

当前阻塞与待跑项：

| 真实方块箱子 `tl-open` 报 `not a container` | 未修，先修 Nukkit 侧方块实体创建路径 |
| 首次 join 的 5×5 区块 + 建 PM Player 超出默认 500ms 硬超时 | 探针服临时调 5000；正式修法见"硬化" |
| 第 8/9/11/12 条（保护区挖掘、实体、换客户端版本、10 分钟跑图） | 未跑 |

下一步不是扩面：先修虚拟容器窗口，再补剩余条目和 C/T 追加项。

### 分级器与插件普查

"加载前告诉你落哪一档"是 README 的核心承诺，而现在只有 `StubProfile` 一张反例表。

- `mukkit classify <phar>`：解包、静态扫符号（类与方法的引用面），对照
  [`graft-map.md`](../design/graft-map.md) 的能力表输出 `native` / `bridged` / `rejected` +
  原因码 + 命中的 API 清单
- 拿它对 30–50 个流行 PM 插件跑一遍，出"缺什么符号"的直方图；这张图就是"按数据补能力"的输入
- 判据：对 20 个已知插件，工具判断与人工判断一致率 ≥ 80%
- 停手条件：一致率 < 60% → 静态扫描不成立（动态探测更贵），回到人工清单，只保留档位表

### 按数据补能力

顺序由分级器的直方图决定，不由"还缺哪个 API"决定。预期前三名（待数据确认）：

| 候选 | 解锁什么 | 为什么可能排前面 |
|---|---|---|
| 容器 GUI（桥内已通） | 箱子商店、菜单、抽奖 | `ContainerOpen` / 内容 / 事务已接；真机待验 |
| 死亡与重生 | 小游戏、PVP、经济惩罚 | 通知层已做（`player.death`）；接管掉落尾部仍是产品决定 |
| 出生点 / 难度 / 玩家名牌 / 飞行 | 大厅、传送、社交 | 都是单字段，成本低 |

- 判据：目标插件清单的通过率上升，每一条都有真机日志或截图证据
- 不做：仍然按 [`events.md`](../design/events.md) 的 A/B 两档，`block.place` / `player.move` /
  容器合成事件不碰

### 硬化与 v1.0

- 背压：`chunk` 入队每 tick 配额、单帧 16 MiB 上限的实际约束、PM 侧区块内存总上限
- 首连预算：首次 join 的区块下发与 PM Player 构建不能撞上硬超时
- Windows：`Transport` 只有 unix socket，文档却写了 TCP——要么实现，要么从文档删掉
- 配置外露：`mirrorRadius` / `mirrorInterval` / `stateInterval` / `worldInterval` 从 `-D`
  挪进 `config.yml`
- 长跑：2 小时 + 20 人 + 跑图；宿主重启后插件状态自愈
- 判据：无 OOM、p99 tick < 5ms、冷启动 < 10 s、README 的安装步骤在干净机器上一次通过

## 不做的事

- **不在桥接层手写 `pocketmine\*` 的同名类。** 需要的行为改 fork，不改这里。
  这是本项目的立身之本，见 [`docs/design/adr/0001-pm-as-host.md`](../design/adr/0001-pm-as-host.md)。
- 不在 PM 侧跑世界 tick。两个模拟器对齐是无底洞，且永远不可能对齐。
- 不为了兼容去改 Nukkit 的包结构。桥要适配 Nukkit，不是反过来。
- 不用 JNI 内嵌 PHP。许可边界会烂，崩溃域也会合并。
- 不承诺"所有 PM 插件都能跑"。承诺的是"加载前告诉你这个插件落哪一档"。
